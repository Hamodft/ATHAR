# Arabic and English profile output

Profile output in all five templates supports Arabic/RTL and English/LTR, with a keyboard-operable language selector and active-state indication. Demo and public profile pages accept `?lang=en` or `?lang=ar`. Demo page controls, headings and explanatory copy follow the selected language. The account workspace and onboarding interface retain their existing Arabic UI; this release adds bilingual profile output and an English content editor.

English content is a separate, bounded `english` object in the existing draft. It contains only name, headline, summary, goal, city, education, courses, skills, contribution and a separate experience list. It cannot introduce contact details, images, account identifiers or publication flags. Editing English does not replace the original fields. English text is entered and reviewed by the owner; no automatic translation or additional AI service has been added.

The English editor is available on `/design` for local drafts and `/edit` for accounts. It shows original content for reference, supports independent English experiences, updates the live design preview, and saves locally. Existing account-save actions persist both versions. Before publishing, the dialog explicitly asks the owner to review both versions; the public snapshot includes only sanitized English content and contact details permitted by the existing sharing choices. Existing published snapshots are not rewritten.

Missing translations use the original profile text with an explicit notice. Fallback paragraphs retain language/direction metadata. The printable CV also offers both languages, preserves original content when English is missing, and disables both language handlers when the account-session logout signal clears the exported document.

`database/bilingual.sql` was applied as `allow_reviewed_english_profile_content`. It expands the existing published-content allowlist to accept an English object, prohibits nested contact/publication keys, and keeps the existing size bound, ownership and RLS. A temporary-table transaction verified valid bilingual input and rejection of an English email field, then rolled back all synthetic test data. RLS remained enabled. The security advisor returned the same pre-existing password-protection notice before and after the change; no new findings or access-policy changes were introduced.

Verification includes language switching across all templates, preservation of source data, privacy sanitation, hostile text escaping, missing/blank translation fallback, English editor persistence, CV switching and logout behavior. Browser checks covered the complete English demo at phone width and the local English editor with a synthetic draft; account-backed publication of a real user's bilingual profile was not performed.
